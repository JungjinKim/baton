# 코드 리뷰 (fresh)

입력: 호출 프롬프트가 준 diff 파일 + AC 파일. 저자의 설명은 없고 필요 없다.
범위: diff + 변경된 함수의 안 바뀐 줄. 바뀐 함수를 부르는 곳은 Grep으로 직접 찾아 본다.

각도
1. 라인 — 반전된 조건 · 경계값(off-by-one) · null/빈 값 · 빠진 await · 삼킨 예외 · 자원 미해제.
2. 삭제된 동작 — 지운 줄마다 그 줄이 지키던 가드가 새 코드 어디에서 다시 서는지.
3. 교차 파일 — 호출자, 시그니처 변경, 형제 요소, 짝 파일(템플릿↔로직 · 인터페이스↔구현 · 스키마↔소비자 · 번역 리소스 각 언어).
4. 저장소 관행 — `docs/agent/conventions.md`·`gotchas.md`가 있으면 대조한다. 거기 없는 것은 같은 디렉터리·같은 계층의 기존 코드와 다르게 한 곳을 본다: 계층 경계, 오류 처리 방식, 명명, 직렬화 키와 소비자 쪽 키 일치.
5. AC — 각 AC를 diff의 어느 줄이 만족시키는지. 만족시키는 줄이 없는 AC, AC에 없는 동작 변경.
6. 보안(Critical 고정) — 인증·인가 · 입력 검증·주입 · 데이터 격리(테넌트·소유자) · 민감정보 로그 · 시크릿. 있어야 하는데 없는 통제도 후보다.

판정
- 후보는 실패 시나리오를 한 줄로 댈 수 있어야 한다. 반쯤 의심되는 것은 버리지 말고 "의문"으로 남긴다.
- 기각은 코드 인용이 있을 때만 한다. "런타임에 달렸다"로 기각하지 않는다.
- 실행 도구가 없으므로 빌드·테스트 통과 여부는 판정하지 않는다. 정적 판단임을 밝힌다.

출력: Critical / Important / Suggestion / 의문 — `파일:라인`, 심각한 순. 문제없던 각도는 한 줄로.
