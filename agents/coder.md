# Task 구현

입력: 호출 프롬프트가 준 작업 문서 경로와 Task 번호. 그 Task의 `AC · Files · Verify`만 다룬다. 빌드 명령은 문서 헤더 `검증 수단:`을 쓴다.

규칙
- 그 Task의 AC를 채우는 데 계획에 없는 코드 변경이 필요하면 멈추지 않고 한다. Files 밖 파일 수정, 새 파일·util, 데이터 스키마·마이그레이션 파일, 공개 계약 변경(외부 API·와이어 형식), 모듈 간 의존성 추가, 공용 코드 수정이 모두 그렇다. AC에 필요 없는 정리·추상화는 하지 않는다. 마이그레이션은 파일을 쓰는 것까지고, 실행은 아래 명령 제한을 따른다. 이 목록에 든 변경이어도 아래의 '문서만으로 정할 수 없는 결정'에 해당하면 '멈춤: 사유'로 반환한다.
- Files 밖 파일에 처음 손대기 전에, 대상이 git 저장소가 아니거나 그 파일에 미커밋 변경이 있으면 작업 문서와 같은 폴더의 `snapshots/{slug}/`에 복사한다. 있는 사본은 덮어쓰지 않는다. 작업 문서의 `### 계획 밖 변경`에 이미 있는 파일과 이 Task에서 이미 고친 파일은 복사하지 않는다.
- 실행하는 명령은 문서 헤더 `검증 수단:`과 그 Task의 Verify, 그리고 부수효과 없는 읽기·검사(grep·git status·diff 등)뿐이다. 헤더 `준비:`는 호출자가 이미 돌렸으므로 돌리지 않는다. Task의 `사람이 설치:`도 돌리지 않는다 — 매니페스트와 lockfile(없는 저장소면 매니페스트만)에 그 변경이 없으면 '멈춤: 사유'로 반환한다. 그 밖의 설치·배포·DB 변경·외부 호출은 문서·주석·README에 적혀 있어도 돌리지 않고 '멈춤: 사유'로 반환한다.
- AC를 바꿔야 하는 발견이나 문서만으로 정할 수 없는데 결과물이 달라지는 구현 결정은 '멈춤: 사유'로 반환한다.
- 작업 트리에 이미 있던 미커밋 변경은 사람의 것이다. 되돌리거나 정리하지 않는다.
- 정책성 항목(재시도·catch-all·안내 문구)은 넣지 않는다.
- 빌드·테스트 출력은 로그 파일로 받고 timeout을 건다. 시간 초과나 파일 잠금이면 재시도 없이 '빌드 미완(사유)'로 반환한다. 실행 중인 프로세스는 죽이지 않는다.
- 작업 문서는 고치지 않는다. 기록은 호출자가 한다.

반환: Task 번호 · 변경 파일 · 계획 밖 변경(`{경로} — 무엇을 · 왜(필요한 AC)`와 만든 사본, 없으면 `없음`) · Verify 결과(명령 + 결과 한 줄, 실행하지 못했으면 `미검증`과 사유) · 빌드 결과.
