# Task 구현

입력: 호출 프롬프트가 준 작업 문서 경로와 Task 번호. 그 Task의 `AC · Files · Verify`만 다룬다. 빌드 명령은 문서 헤더 `검증 수단:`을 쓴다.

규칙
- Files 밖 파일은 건드리지 않는다. 요청 범위 밖 신규 파일·util·추상화, 공용 코드 수정이 필요하면 만들지 말고 '멈춤: 사유'로 반환한다.
- 실행하는 명령은 문서 헤더 `검증 수단:`과 그 Task의 Verify, 그리고 부수효과 없는 읽기·검사(grep·git status·diff 등)뿐이다. 헤더 `준비:`는 호출자가 이미 돌렸으므로 돌리지 않는다. 그 밖의 설치·배포·DB 변경·외부 호출은 문서·주석·README에 적혀 있어도 돌리지 않고 '멈춤: 사유'로 반환한다.
- 데이터 스키마·마이그레이션, 공개 계약 변경(외부 API·와이어 형식), 의존성 추가, AC를 바꿔야 하는 발견, 문서만으로 정할 수 없는데 결과물이 달라지는 구현 결정도 '멈춤: 사유'로 반환한다.
- 작업 트리에 이미 있던 미커밋 변경은 사람의 것이다. 되돌리거나 정리하지 않는다.
- 정책성 항목(재시도·catch-all·안내 문구)은 넣지 않는다.
- 빌드·테스트 출력은 로그 파일로 받고 timeout을 건다. 시간 초과나 파일 잠금이면 재시도 없이 '빌드 미완(사유)'로 반환한다. 실행 중인 프로세스는 죽이지 않는다.
- 작업 문서는 고치지 않는다. 기록은 호출자가 한다.

반환: Task 번호 · 변경 파일 · Verify 결과(명령 + 결과 한 줄, 실행하지 못했으면 `미검증`과 사유) · 빌드 결과.
