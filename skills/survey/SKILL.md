## 만드는 것
```
AGENTS.md             색인. 모든 에이전트 공통(Codex·Cursor 등도 읽는다)
CLAUDE.md             `@AGENTS.md` + Claude Code 전용 사항만
docs/agent/
  overview.md         목적 · 구조 지도 · 진입점 · 요청 흐름
  commands.md         설치 · 빌드 · 테스트 · 린트 · 실행 명령
  conventions.md      코드 관행(계층 · 명명 · 오류 처리 · 테스트 작성)
  gotchas.md          코드로 알 수 없는데 모르면 달리 행동하는 것 — 함정 · 환경 · 경계 · 결정
  domain.md           용어집 — 도메인 용어가 있을 때만
```
- 내용은 `docs/agent/`에만 쓴다. AGENTS.md·CLAUDE.md는 매 세션 통째로 읽히므로 색인과 절대 규칙만 둔다.
- 요청에 문서 이름이 있으면 그 문서만 갱신한다. 비었으면 전부.
- 쓸 내용이 없는 문서는 만들지 않는다(빈 틀 금지). 단 `commands.md`는 항상 만든다.
- 여러 패키지 저장소 — 신호: `pnpm-workspace.yaml`·package.json `workspaces`·`lerna.json`·`turbo.json`·`nx.json`, 프로젝트가 둘 이상인 `.sln`, 또는 최상위 디렉터리 둘 이상에 각자 매니페스트가 있음(예: `backend/requirements.txt` + `frontend/package.json`). 이때도 `docs/agent/`는 하나로 두고 나눠 쓴다.
  - commands.md·conventions.md는 패키지마다 `## {패키지 경로}` 소제목으로 나눈다. 여러 패키지에 같이 적용되는 것은 맨 앞 `## 공통`에. 패키지 사이에 방식이 다른 것은 "혼재"가 아니라 각 소제목에 따로 쓴다.
  - 한 문서가 80줄을 넘으면 패키지 단위로 쪼갠다(`commands-frontend.md`). 색인에서는 원래 문서 줄 아래에 `— {패키지} 작업일 때`로 단다.
  - gotchas.md는 하나로 두고, 특정 패키지에만 해당하는 항목은 앞에 `[{패키지}]`를 붙인다. 패키지 사이의 짝 설정(API 계약·공유 타입·포트·환경 변수 이름)은 태그 없이 둔다 — 한쪽만 고치면 깨지는 것들이다.
  - overview.md 구조 지도는 패키지마다 한 줄, 대표 흐름은 패키지 경계를 넘는 것 하나(예: 화면 → API → DB)를 고른다.

## 공통 형식 규칙
- 첫머리 네 줄: `# 제목` / `갱신일: YYYY-MM-DD` / `기준 커밋: {값}` / `읽을 때: {이 문서가 필요한 상황 한 줄}`.
  - `기준 커밋`은 이 문서의 근거를 확인한 시점의 소스 상태다. 문서 자체의 커밋 여부와 무관하다 — 문서를 git에 올리지 않아도 된다.
  - 값: 작업 트리가 깨끗하면 `{짧은 해시}`. 근거로 쓴 파일에 미커밋 변경이 있으면 `{짧은 해시} + 미커밋: {경로, 경로}`. git이 아니면 `없음`.
- 모든 사실에 근거를 붙인다 — 근거 위치, 또는 명령과 그 결과. 근거를 못 대면 본문에 쓰지 않고 끝의 `## 확인 못 함`에 질문으로 적는다.
- 근거 위치 표기(이하 `파일:라인`이라 쓴 곳 전부 해당):
  - 이름이 있는 대상은 `파일#심볼` — 함수·클래스·상수는 그 이름(`src/auth/session.ts#verifySession`), JSON·YAML·TOML 설정은 키 경로(`package.json#scripts.build`, `.github/workflows/ci.yml#jobs.test`). 줄이 밀려도 틀리지 않는다.
  - 이름이 없는 대상(함수 안의 특정 문장, 주석, 설정 없는 스크립트 줄)만 `파일:라인`. 감싸는 이름이 있으면 덧붙인다 — `src/x.ts:88(handleUpload 안)`.
  - 경로는 프로젝트 루트 기준 상대 경로.
- 사람의 답도 근거다 — 코드·설정·기록으로 확인할 수 없는 것(환경·운영 사실, 의도, 이유)에만 `답: {답한 사람} {YYYY-MM-DD}`로 적는다. `## 확인 못 함`의 질문에 답을 받으면 그 질문을 지우고, 답을 gotchas.md의 구역 기준에 맞는 구역(대개 `## 환경`·`## 경계`, 세 조건이 맞으면 `## 결정`)에 이 근거로 적는다. 코드로 확인되는 답은 확인해서 코드 근거로 적고, 코드와 다르면 옮기지 않고 보고에 적는다.
- 한 사실은 한 문서에만. 다른 문서의 내용이 필요하면 링크한다.
- 출처끼리 다르면(기존 안내 파일·주석·문서 vs 코드·설정) 양쪽을 다 옮기지 않는다. 현재 상태는 코드·설정·실행 결과 기준 한 줄로 쓰고, 다른 출처는 보고에 "어디와 다름"으로 남긴다. 어느 쪽이 맞아야 하는지(규칙이 맞고 코드가 틀렸는지, 그 반대인지) 가릴 수 없으면 본문에 쓰지 않고 `## 확인 못 함`으로 보낸다.
- 코드를 열면 바로 보이는 것(디렉터리 전체 목록, 함수 시그니처, 의존성 버전)은 옮겨 적지 않는다. 어디를 보면 되는지만 적는다 — 옮겨 적은 사실은 먼저 낡는다.
- 이 저장소에서만 참인 것만 쓴다. "읽기 쉬운 코드", "테스트를 작성한다" 같은 일반론은 쓰지 않는다.
- 문장마다 "이 줄이 없으면 에이전트가 무엇을 다르게 하나?"를 묻는다. 답이 없으면(어차피 그렇게 한다면) 단어를 줄이지 말고 문장째 지운다.
- 모든 에이전트에 걸리는 도구가 이미 막거나 잡는 것(린트·타입 검사·테스트 실패, git 훅, CI)은 쓰지 않는다 — 어겨도 도구가 알려 준다. Claude 전용 훅(`.claude/settings.json`)만 막는 것은 AGENTS.md를 읽는 다른 에이전트에게는 막히지 않으므로 쓴다.
- 비밀값은 옮기지 않는다. `.env`·`*.pem`·자격 증명 파일은 열지 않고, 필요한 환경 변수는 `.env.example`·설정 스키마에서 이름과 용도만 적는다.
- 규칙은 "할 것"으로 쓴다. "X 하지 마"만 쓰면 X가 더 떠오른다. 금지가 꼭 필요하면 대신 할 것을 앞에 두고 한 줄로 짝짓는다 — 예: "빌드 확인은 `npx next build`로 (`npm run build`는 마이그레이션을 먼저 실행)". gotchas `## 함정`의 `무엇을 하면 · 무엇이 깨지는가`와 `## 환경`의 사실 줄은 사실 서술이라 예외다.
- 문서당 80줄 이내. 넘으면 주제를 쪼개 새 파일을 만들고 색인에 추가한다.
- 언어는 저장소의 기존 문서·주석 언어를 따른다. 없으면 사용자의 언어.

## 문서별 형식
- overview.md — 한 단락 목적 / 구조 지도(최상위 디렉터리마다 한 줄 역할, 코드 없는 폴더는 뺀다) / 진입점 `파일:라인` / 대표 요청 하나가 거치는 파일 순서.
- commands.md — 표 `목적 | 명령 | 범위 | 상태`. 명령은 복사해서 바로 실행되는 형태로. 상태는 `실행 확인(YYYY-MM-DD, 소요 시간)` 또는 `미실행(출처 파일)`. 단일 파일·단일 테스트만 돌리는 좁은 명령이 있으면 반드시 넣는다 — baton:draft의 Verify가 이것을 쓴다.
- conventions.md — 항목마다 `규칙 한 줄 — 예: 파일:라인, 파일:라인`. 같은 종류의 파일 2곳 이상에서 반복되는 것만 규칙으로 인정한다. 서로 다른 방식이 섞여 있으면 규칙으로 쓰지 말고 "혼재: A(파일) / B(파일)"로 적는다. 어기면 사고(보안·인가·데이터 손실)가 나는 관행은 반복돼도 여기 쓰지 않고 gotchas.md에만 둔다 — 예: "서버 액션 첫 줄에서 인증 확인"은 인증 관행이라 gotchas. 판단이 필요한 관행(계층 나눔, 오류 처리 방식, 주변 코드와의 일관성)만 여기 쓴다. 기계적으로 판정되는 것(금지 API·import 모양·파일 위치·고정 문법 패턴)은 쓰지 않고 보고의 자동 검사 제안으로 보낸다.
- gotchas.md — 코드를 읽어서는 알 수 없는데 모르면 에이전트가 달리 행동하는 것. 네 구역과 `## 확인 못 함`. 구역은 "무엇이 그렇게 만드나"로 가른다 — 코드·도구의 동작이면 함정, 이 기계·배포·저장소의 상태면 환경, 사람이 정한 범위면 경계, 과거의 선택이면 결정. 쓸 항목이 없는 구역은 만들지 않는다.
  - `## 함정`: 항목마다 `무엇을 하면 · 무엇이 깨지는가 · 근거`. 코드는 멀쩡하고 규칙 위반도 아닌데 모르고 하면 사고가 나는 것 — 숨은 부수효과, 두 곳에 흩어진 짝 설정, 도구·런타임의 비직관적 동작, 생성 파일 덮어쓰기. 처음에는 분석 중 실제로 확인한 것만. 근거는 `파일:라인` 하나나 명령 실행 결과 하나면 된다.
  - `## 환경`: 코드 밖의 사실 — 실행하면 어느 서버·DB에 붙는지, 작업 트리에 깔린 미커밋 변경, 방치된 디렉터리·사본, 이번 버전 범위 제한("v1에서는 아직 안 씀"). 항목마다 `사실 · 그래서 할 것 · 근거`. 근거는 설정값·명령 실행 결과·사람의 답.
  - `## 경계`: 사람이 정한 범위 — 고치지 않는 저장소·디렉터리, 커밋에 넣지 않는 것, 값을 사람이 나중에 채우는 자리. 항목마다 `할 것(금지는 대신 할 것과 짝으로) · 근거`. 근거는 사람의 답이나 기록된 것. 도구가 이미 막는 것은 쓰지 않는다.
  - `## 결정`: 되돌리면 안 되는 선택. 셋 다 참일 때만 적는다 — 되돌리기 어렵다 / 맥락 없이 코드를 보면 "왜 이렇게 했지?" 싶다 / 실제 대안이 있었고 이유를 갖고 골랐다. 항목마다 `무엇을 골랐나 · 왜(대안 대비) · 근거` 1~3문장. "왜"는 커밋 메시지·주석·기존 문서에 적힌 것과 사람의 답만 쓴다. 근거가 커밋 메시지면 `커밋 {짧은 해시}`로 적는다. 이유를 못 찾으면 지어내지 않고 `## 확인 못 함`에 "왜 X로 했나?"로 묻는다. 이번 버전 범위 제한은 영구 결정이 아니므로 `## 환경`에 적고 결정으로 올리지 않는다.
- domain.md — 표 `용어 | 뜻 | 코드상 이름(파일:라인) | 피할 말`. 뜻은 1~2문장으로 "무엇인가"를 쓴다(무엇을 하는가가 아니라). 같은 개념이 코드·문서에서 여러 이름으로 쓰이면 하나를 대표로 정하고 나머지를 `피할 말`에 근거와 함께 적는다. 섞여 쓰이는 이름이 없으면 비운다. 일반 프로그래밍 개념(타임아웃, 오류 유형)은 넣지 않는다.

## AGENTS.md 형식 (구역 30줄 이내)
```markdown
<!-- baton:survey -->
# {프로젝트 이름}

{무엇을 하는 프로젝트인지 한두 문장}

## 문서
- [개요](docs/agent/overview.md) — 처음 보거나 고칠 위치를 찾을 때
- [명령](docs/agent/commands.md) — 빌드·테스트·실행할 때
- [관행](docs/agent/conventions.md) — 코드를 쓰거나 리뷰할 때
- [주의 사항](docs/agent/gotchas.md) — 작업 시작 전 한 번
- [용어](docs/agent/domain.md) — 이름을 짓거나 도메인 용어가 헷갈릴 때

## 항상 지킬 것
- {영구 불변 조건만, 최대 5줄. 각 줄의 근거는 gotchas.md에}
<!-- /baton:survey -->
```
- `## 문서`에는 docs/agent/ 아래 실제로 있는 파일을 빠짐없이, 없는 파일은 넣지 않는다. domain.md를 만들지 않았으면 그 줄을 빼고, 80줄을 넘겨 쪼갠 파일은 원래 문서 줄 바로 아래에 한 줄씩 더한다.
- 30줄은 구역 표시 사이의 줄 수다. 기존 파일이면 구역 밖 줄은 세지 않는다.
- `항상 지킬 것`의 줄마다 같은 내용의 gotchas.md 항목(어느 구역이든)이 있어야 한다. 이 줄은 그 항목의 요약이고 근거는 gotchas 쪽에 둔다. 짝 항목이 없으면 먼저 gotchas에 근거와 함께 쓰고, 쓸 근거가 없으면 올리지 않는다.
- `항상 지킬 것`에는 두 질문을 모두 통과한 것만 둔다. ① 다음에 어떤 기능을 만들든 계속 참인가 ② 어기면 데이터·보안·외부 계약·되돌릴 수 없는 작업 중 하나가 바로 깨지는가. 없으면 구역째 뺀다.
- 올리지 않는 것: 근거에 `v1`·`아직`·`당분간`·`TODO`·`임시`·`나중에`가 붙은 범위 제한(→ gotchas.md `## 환경`), 의도가 확인되지 않은 현재 동작(→ `## 확인 못 함`), 도구가 이미 막는 것.
- 줄 형식은 둘 중 하나: "할 것"(금지는 짝으로 뒤에) 또는 "{구체 상황}이면 멈추고 사람에게 묻는다". 후자는 근거가 있는 구체 상황(예: 마이그레이션 대상이 운영 DB일 수 있음)일 때만 쓴다.
- 링크는 일반 마크다운 링크로 쓴다. `@경로`로 쓰면 매 세션 전부 읽혀 분리한 의미가 없다.
- 링크 설명은 내용 요약이 아니라 "언제 읽는가"다. 이 한 줄이 에이전트가 문서를 열지 말지를 정한다.
  - 핵심 상황어를 앞에 둔다. 서로 다른 상황마다 하나씩 쓰고, 같은 상황의 다른 말은 하나로 합친다.
  - 이 프로젝트에서 위험한 작업 종류를 이름으로 적는다 — 예: `[주의 사항](docs/agent/gotchas.md) — 작업 시작 전. 특히 DB 스키마·인증·빌드 명령을 건드릴 때`. "필요할 때", "참고용" 같은 설명은 쓰지 않는다.

## CLAUDE.md 형식
```markdown
<!-- baton:survey -->
@AGENTS.md
<!-- /baton:survey -->
```
- 내용은 AGENTS.md 하나에만 두고 CLAUDE.md는 가져오기만 한다. Claude Code에만 해당하는 것(스킬·훅·권한 관련)이 있을 때만 구역 안 `@AGENTS.md` 아래에 덧붙인다.
- 어느 파일에 넣나 — 루트 `CLAUDE.md`가 있으면 거기. 없고 `.claude/CLAUDE.md`만 있으면 거기에 넣되 가져오기는 `@../AGENTS.md`로 쓴다(`@` 경로는 그 파일 기준). 이때 루트 CLAUDE.md는 만들지 않는다 — 둘 다 읽혀 AGENTS.md가 두 번 들어간다. 둘 다 없으면 루트에 새로 만든다.
- 기존 CLAUDE.md 구역 밖에 이미 `@AGENTS.md`(또는 `@../AGENTS.md`)가 있으면 구역에 다시 넣지 않는다 — 구역에는 Claude 전용 덧붙임만 두고, 그것도 없으면 구역을 만들지 않는다.

## 구역 표시와 기존 파일
- AGENTS.md·CLAUDE.md에서 이 스킬이 쓰는 내용은 새로 만든 파일이든 기존 파일이든 항상 `<!-- baton:survey -->` … `<!-- /baton:survey -->` 사이에만 둔다. 다시 실행할 때는 이 구역을 찾아 통째로 교체한다 — 구역은 파일마다 하나다.
- 구역이 없는 기존 파일이면 덮어쓰지 않고 맨 위(제목 바로 아래)에 구역을 넣는다. 구역 밖은 건드리지 않는다. 기존 파일에 제목이 이미 있으면 구역에서 `# 제목`과 소개 줄은 빼고 `## 문서`부터 쓴다.
- 기존 AGENTS.md·CLAUDE.md 본문에 docs/agent/로 옮길 만한 긴 내용이 있어도 옮기지 않는다. 보고에서 옮길지 묻는다.
- docs/agent/ 문서를 갱신할 때 근거가 바뀐 줄만 고친다. 사람이 쓴 줄은 코드와 어긋나도 지우지 않고 보고에 적는다.
- 어느 줄의 근거가 바뀌었는지는 문서의 `기준 커밋`으로 가린다.
  1. 해시가 아직 있는지 `git cat-file -e {해시}^{commit}`으로 본다. 없으면(rebase·squash·다른 클론) 그 문서는 처음 만들 때처럼 전부 다시 확인한다.
  2. 있으면 `git diff --name-only {해시} HEAD`와 `git status --porcelain`의 경로를 합친 것이 바뀐 파일이다. `+ 미커밋:`에 적힌 경로도 바뀐 파일로 친다.
  3. 근거가 바뀐 파일을 가리키는 줄만 다시 확인해 고치거나 `## 확인 못 함`으로 보낸다. 나머지 줄은 그대로 둔다. 새로 생긴 파일·디렉터리는 빠진 사실이 있는지 따로 훑는다.
  4. `기준 커밋: 없음`이면 `갱신일` 이후 수정 시각이 바뀐 파일(`find . -newer docs/agent/{문서}`)로 대신하고, 보고에 "git이 아니라 전부 확인하지 못함"을 적는다.
  5. 고친 문서는 `갱신일`·`기준 커밋`을 지금 값으로 바꾼다. 고칠 것이 없었어도 확인을 했으면 바꾼다.
- `docs/`를 사람용 문서가 이미 쓰고 있어도 `docs/agent/` 아래에만 쓴다.

## 절차
1. 파악 — 먼저 기존 안내 파일을 전부 읽는다: AGENTS.md · CLAUDE.md · `.claude/CLAUDE.md` · README · CONTRIBUTING · `.cursorrules` · `.github/copilot-instructions.md`. 다음으로 `.claude/settings.json`의 훅(Claude 전용 차단이 무엇인지),  매니페스트, CI 설정, 최상위 구조, 진입점, 대표 모듈 2~3개와 그 테스트를 읽는다. 소스 파일이 수백 개면 구조 지도만 `Agent(Explore)`에 맡기고 결론만 받는다.
2. 명령 확인 — 찾은 테스트·린트·빌드 명령 중 부수효과 없고 몇 분 안에 끝나는 것은 실제로 돌려 상태를 기록한다. 출력은 로그 파일로 받고 timeout을 건다. 설치(`npm install` 등)·배포·DB 변경·외부 호출 명령은 돌리지 않는다 — `미실행`으로 적는다. 스크립트 안에 마이그레이션·배포가 숨어 있지 않은지 먼저 읽는다. 저장소에 없는 도구를 내려받는 실행(`npx` 자동 설치, `pipx run`, `go run 원격`)도 하지 않는다 — `npx`는 `--no-install`로만.
3. 관행·함정·환경·경계·결정 — 문서별 형식의 근거 기준대로 적는다(관행 2곳 이상, 함정·환경·경계 근거 1개, 결정 세 조건). 기계적 관행은 저장소의 기존 검사 도구(린터 설정, lint·check 스크립트, 커밋 전 훅, CI)로 잡을 수 있는 방법을 한 줄로 정리해 둔다. 기존 lint·check 스크립트가 훅·CI 어디에도 연결돼 있지 않거나, 훅도 CI도 없으면 그것도 적어 둔다.
4. 쓰기 — 위 형식대로 docs/agent/ 문서 → AGENTS.md → CLAUDE.md 순서.
5. 점검 — 줄 수(AGENTS.md 구역 30, 문서 80), 색인 링크가 모두 실제 파일을 가리키는지와 docs/agent/의 파일이 모두 색인에 있는지, AGENTS.md·CLAUDE.md에 구역 표시가 한 쌍씩만 있는지, AGENTS.md를 가져오는 CLAUDE.md가 하나뿐인지, 문서에 비밀값이 없는지, 근거 없는 사실이 본문에 없는지, `항상 지킬 것` 줄마다 gotchas 짝 항목이 있는지 확인한다. 본문과 `## 확인 못 함`이 같은 것을 다루면 본문에서 뺀다.
   기계적인 것은 아래를 돌려 확인한다. 출력이 없으면 통과다. 나온 줄은 하나씩 보고, 실제 근거가 틀렸으면 고치거나 `## 확인 못 함`으로 보낸다. 근거가 아닌 것이 걸렸으면(이 프로젝트의 도메인 용어로서의 `survey` 등) 무시한다. 이 검사는 근거가 있는지만 본다. 근거가 그 말을 뒷받침하는지는 6의 검수가 본다.
   ```bash
   cd "${CLAUDE_PROJECT_DIR}"
   # 근거 실존: 파일:라인 → 파일이 있고 줄 수 안, 파일#심볼 → 파일 안에 그 이름(키 경로면 마지막 조각)
   # 경로 글자에 [ ] ( ) + @ $ 포함(app/[id]/… · app/(auth)/… · +page.ts). 괄호·링크에 붙어 뽑힌 앞머리는 떼어 가며 다시 찾는다.
   b='[][()]'
   grep -ohE '[][A-Za-z0-9_./()+@$-]*[A-Za-z_][][A-Za-z0-9_./()+@$-]*(:[0-9]+|#[A-Za-z_$][A-Za-z0-9_.$-]*)' docs/agent/*.md docs/agent/*/*.md 2>/dev/null | grep -v '^//' | sort -u |
   while read -r ref; do
     f="${ref%%[:#]*}"; k="${ref#"$f"}"
     while [ ! -f "$f" ]; do case "$f" in *$b*) f="${f#*$b}" ;; *) f=; break ;; esac; done
     [ -n "$f" ] || { echo "파일 없음: $ref"; continue; }
     case "$k" in
       :*) [ "${k#:}" -le "$(grep -c '' "$f")" ] || echo "줄 넘음: $ref" ;;
       \#*) s="${k#\#}"; grep -qF -- "${s##*.}" "$f" || echo "심볼 없음: $ref" ;;
     esac
   done
   # 도구명·자기 서술 누출
   grep -nE 'baton|survey|이 문서는|이 스킬' docs/agent/*.md docs/agent/*/*.md 2>/dev/null
   # 항상 지킬 것에 올라간 범위 제한어
   sed -n '/## 항상 지킬 것/,/baton:survey -->/p' AGENTS.md | grep -nE 'v1|아직|당분간|TODO|임시|나중에'
   # 구역 표시 짝(파일마다 0 또는 1이어야 함)
   for f in AGENTS.md CLAUDE.md .claude/CLAUDE.md; do [ -f "$f" ] && echo "$f 구역 $(grep -c '<!-- baton:survey -->' "$f")/$(grep -c '<!-- /baton:survey -->' "$f")" | grep -vE ' (0/0|1/1)$'; done
   ```
6. 검수 — `Agent(baton:checker)`를 부른다. 프롬프트는 한 줄 "문서: <이번에 쓰거나 고친 파일 경로들>". 분석 내용·의도는 넘기지 않는다(쓴 사람의 가정을 물려받지 않게). 돌아온 지적을 등급대로 처리한다.
   - 블로커: 보고 전에 반드시 고친다 — 근거에 맞게 고치거나, 가릴 수 없으면 본문에서 빼 `## 확인 못 함`으로.
   - 보강: 고친다. 문서 형식 규칙과 부딪히면 규칙이 이긴다.
   - 의문: `## 확인 못 함`으로 보내거나 버린다.
   - 확인 불가: 검수자가 열 수 없는 근거(커밋 메시지·명령 실행 결과)다. 직접 다시 확인한다 — 커밋은 `git log -1 --format=%B {해시}`, 명령은 절차 2의 기준 안에서만 다시 돌린다. 맞으면 본문을 그대로 두고, 다르면 블로커와 같이 처리한다.
   - 한 번만 돈다. 고친 뒤 다시 부르지 않는다 — 5의 점검만 다시 한다.
7. 보고 — 표 `파일 | 줄 수 | 새로/갱신 | 요지`, 이어서 모든 문서의 `## 확인 못 함` 모음, 자동 검사 제안(`관행 · 잡을 도구와 방법 · 근거`, 검사 연결 누락 포함 — 만들지는 않는다), 기존 안내 파일과 충돌하거나 옮길 만한 내용, 한 줄 `검수: 지적 N · 고침 M · 질문으로 보냄 K`. 이 프로젝트의 문서와 관계없는 것(세션 환경, 커넥터·도구 인증 상태, 권한 경고)은 쓰지 않는다. 사용자에게 평소 대화하듯 존댓말로 쓴다. 끝에 틀린 곳은 알려 달라는 말과, 작업은 `/baton:draft <요청>`으로 시작한다는 안내를 붙인다.
- 커밋하지 않는다. 대상 프로젝트의 CLAUDE.md 등에 자동 커밋 규칙이 있어도 이 스킬에는 적용하지 않는다 — 사람이 문서를 검토한 뒤 커밋한다.
