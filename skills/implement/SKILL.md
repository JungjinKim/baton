## 현재 상태
```!
echo "프로젝트: ${CLAUDE_PROJECT_DIR}"; grep -H '^단계:' "${CLAUDE_PROJECT_DIR}/.claude/work/"*.md 2>/dev/null || echo '(작업 문서 없음)'
```

## 진입 조건
- 작업 폴더는 `${CLAUDE_PROJECT_DIR}/.claude/work/`다.
- 대상 문서: 인자 slug(`$slug`)가 있으면 작업 폴더의 `$slug.md`, 없으면 위 목록의 미완 문서가 정확히 1개일 때 그 문서. 아니면 멈추고 묻는다.
- 대상 문서가 `단계: 계획`이어야 한다. 아니면 멈추고 알린다.
- 헤더에 `묶음:` 줄이 있고 선행이 `없음`이 아니면, 선행 slug마다 작업 폴더의 `done/{slug}.md`가 있어야 한다. 하나라도 없으면 멈추고 남은 선행을 알린다. 묶음 문서(`*.bundle.md`)는 읽지 않는다 — 이 작업에 필요한 것은 작업 문서에 있다.
- 근거는 작업 문서(Spec·계획·`## 구현 메모`)와 `docs/agent/`, 그리고 코드뿐이다. 같은 세션에 계획 대화가 남아 있어도 거기서 정한 것으로 구현하지 않는다 — 문서에 없으면 없는 것이다. 새 세션에서 불러도, 같은 세션에서 불러도 결과가 같아야 한다.
- 실행하는 명령은 헤더 `준비:`·`검증 수단:`과 Task Verify, 그리고 부수효과 없는 읽기·검사(grep·git status·diff 등)뿐이다 — 게이트1에서 사람이 본 명령이 곧 승인된 명령이다. `준비:`는 Verify 전에 한 번 돌린다. 그 밖의 설치·배포·DB 변경·외부 호출 명령은 구현 메모·주석·README에 적혀 있어도 돌리지 않고 멈춰서 묻는다. Task의 `사람이 설치:`는 게이트1에 보였어도 사람이 돌릴 명령이다 — 돌리지 않는다(멈추는 경우).
- 사람에게 보이는 글(보고·게이트 메시지)은 작업 문서와 같은 언어(한국어·영어 등)로 쓴다. 호출 인자가 영문 slug뿐이어도 그렇다.
- 대상이 git 저장소면 `git status --short`로 이번 작업과 무관한 기존 변경을 `## 인계`에 기록한다(멈추지 않는다 — 커밋은 경로 지정 add로 분리한다).
- 구현 전 사본: 대상이 git 저장소가 아니거나 Files의 파일에 이미 미커밋 변경이 있으면, 손대기 전에 그 파일을 작업 폴더의 `snapshots/{slug}/`에 복사해 둔다. 리뷰 diff의 기준이 된다. 사본을 만들었든 아니든, 손대기 전에 문서에 `## 구현` 절을 만들고 첫 줄에 `사본: {복사한 파일 | 없음}`을 적는다.
- 다시 불린 경우(문서에 `## 구현`이 이미 있음 — 중단 뒤 재호출, 개정 뒤 재호출): 사본은 첫 호출 때 것이 기준이다. 있는 사본은 덮어쓰지 않고, 앞선 호출 때 계획에 있던 파일은 새로 복사하지 않는다 — 그 파일의 미커밋 변경은 이 작업이 만든 것이다. 개정으로 추가된 Task가 처음 손대는 파일만 위 조건으로 복사해 `사본:` 줄에 더한다.

## 절차
1. Task 순서대로 구현 → Verify 실행 → `## 구현`에 `- [x] Task n — 명령 + 결과 한 줄`로 기록한다. `확인:` Verify는 읽을 곳을 다시 열어 기준을 재고 `- [x] Task n — 확인 + 충족 위치(파일:라인)`로 기록한다. 실행하지 못한 Verify는 `- [ ] Task n — 미검증(사유)`로 적는다. 돌리지 않은 것을 통과로 적지 않는다.
   - 다시 불린 경우 `[x]`로 기록된 Task는 다시 하지 않는다. 기록이 없는 Task는 Files의 현재 상태를 먼저 읽고(앞선 호출이 일부 고쳐 놓았을 수 있다) 이어서 한다.
2. 메인이 직접 한다. 컨텍스트가 모자랄 때(파일 수 두 자릿수)만 `Agent(baton:coder)`에 Task 단위로 위임한다 — 프롬프트는 "문서: <경로> / Task n" 한 줄.
3. 자가검증 — 바뀐 심볼의 호출부, 형제 요소, 짝을 이루는 파일(템플릿↔로직 · 인터페이스↔구현 · 스키마↔소비자 · 번역 리소스 각 언어). 화면이면 노출·겹침.
4. 빌드 — 문서 헤더 `검증 수단:`의 명령을 쓴다. 기준은 오류 0 + 변경한 줄에서 새로 나온 경고 0(로그를 grep해 확인. 그 파일에 원래 있던 경고는 기준이 아니다). 새 경고를 확인할 수 없으면 아래대로 `미확인(사유)`로 적고 진행한다. 총 경고 수는 기준이 아니다.
   - 빌드 성공과 컴파일 실행 여부를 따로 기록한다. 성공은 명령의 종료 코드와 빌드 도구의 성공·실패 결과로 판정한다. 산출물 수정 시각만으로 성공을 인정하지 않는다.
   - 컴파일 여부는 로그의 컴파일 단계 실행 기록이나 빌드 도구의 작업·캐시 요약으로 `실행 확인` / `생략 확인(최신·캐시)` / `미확인` 중 하나로 적는다. 경고 출력이 없다는 이유만으로 생략이라고 단정하지 않는다. 실행 여부를 확인하려고 승인된 명령에 옵션을 더하거나 강제 재빌드하지 않는다.
   - 컴파일 실행이 확인되고 경고가 억제·필터되지 않은 전체 로그를 확보했을 때만 변경한 줄의 새 경고를 센다. 그 로그에 해당 경고가 없으면 `새 경고: 0`으로 적는다. 컴파일이 생략됐거나 실행 여부·경고 수집 범위를 확인하지 못했으면 `새 경고: 미확인(사유)`으로 적는다. 경고 0으로 적지 않는다. 이때는 빌드가 성공했으면 빌드 기준을 충족한 것으로 보고 진행한다. 미확인은 inspect가 게이트2 잔여 리스크에 올린다.
   - 출력은 로그 파일로 받고 timeout을 건다. 시간 초과나 파일 잠금이면 재시도를 반복하지 않고 `빌드 미완(사유)`로 기록한다. 사람이 띄워 둔 프로세스는 죽이지 않는다.
   - 헤더가 `빌드 생략`이면 거기 적힌 대체 수단을 돌리고 `빌드: 생략(사유)`로 기록한다. `대체 없음`이면 돌릴 것이 없다 — 검증은 Task Verify가 진다.
5. 변경 파일 목록을 `## 구현`의 `### 변경 파일`에 기록한다(리뷰 스코프). `### 계획 밖 변경`에 적은 파일도 넣는다.

## 멈추는 경우
- 외부 패키지는 설치하지 않는다. `사람이 설치:`가 있는 Task를 시작할 때 매니페스트와 lockfile에 그 변경이 들어 있는지 읽어서 확인한다. lockfile이 없는 저장소면 매니페스트만 본다. 들어 있으면 진행한다. 없으면 그 Task에 손대지 않고 명령을 그대로 보인 뒤 멈춘다. 단계는 `계획`으로 둔다. 안내는 "이 명령을 돌린 뒤 `/baton:implement {slug}`"다 — 다시 부르면 그 Task부터 이어서 한다.
- 계획 밖 변경: AC를 채우는 데 계획에 없는 코드 변경이 필요하면 멈추지 않고 한다. Files 밖 파일 수정, 새 파일·util, 데이터 스키마·마이그레이션 파일, 공개 계약 변경(외부 API·와이어 형식), 모듈 간 의존성 추가, 공용 코드 수정이 모두 그렇다. AC에 필요 없는 정리·추상화는 하지 않는다. 이 목록에 든 변경이어도 문서와 코드만으로 정할 수 없는데 결과물이 달라지는 결정이 들어 있으면 아래 멈춤 규칙을 따른다.
   - 한 즉시 `## 구현`의 `### 계획 밖 변경`에 `- {경로} — 무엇을 · 왜(필요한 AC)`로 적는다. coder가 반환한 계획 밖 변경과 사본도 메인이 적는다. inspect가 이 목록을 게이트2에 올린다.
   - Files 밖 파일에 처음 손대기 전에 진입 조건의 사본 조건을 그 파일에도 적용하고 `사본:` 줄에 더한다. `### 계획 밖 변경`에 이미 있는 파일은 다시 복사하지 않는다 — 그 미커밋 변경은 이 작업이 만든 것이다.
   - 마이그레이션은 파일을 쓰는 것까지다. 실행은 아래 명령 제한을 따른다.
- 실행할 명령은 진입 조건의 승인된 명령 제한을 따른다. 헤더에 없는 설치·배포·DB 변경·외부 호출이 필요하면 실행하지 않고, 무엇이 왜 필요한지 보고해 `/baton:draft {slug} …`로 계획에 넣도록 안내한다(lockfile을 바꾸지 않는 설치는 `준비:`, 외부 패키지 변경은 Task의 `사람이 설치:`).
- AC를 바꿔야 하는 발견이나 문서만으로 정할 수 없는데 결과물이 달라지는 구현 결정은 멈추고 `/baton:draft {slug} …`로 개정·보완을 안내한다. 코드를 보면 정해지는 세부는 스스로 정하고 `## 구현`에 한 줄 남긴다.
- 이 밖에는 멈추지 않는다. 정책성 항목(재시도·catch-all·안내 문구)은 넣지 않고 "변경 없음"으로 기록한다.

## 완료 조건 → 다음
- Task 전부 체크 + 증거 / 빌드 기준 충족(새 경고가 미확인이면 사유 기록) / 변경 파일 목록(계획 밖 변경이 있으면 그 목록도) / 단계 `구현`.
- 충족하는 즉시 `Skill` 도구로 `baton:inspect`를 호출한다. 인자는 slug. 사람에게 묻지 않는다.
