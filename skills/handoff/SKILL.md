## 현재 상태
```!
echo "프로젝트: ${CLAUDE_PROJECT_DIR}"; echo "오늘: $(date +%F)"; echo '--- 기존 핸드오프 ---'; ls -1t "${CLAUDE_PROJECT_DIR}/.claude/work/handoff/"*.md 2>/dev/null || echo '(없음)'; echo '--- baton 작업 문서 ---'; grep -H '^단계:' "${CLAUDE_PROJECT_DIR}/.claude/work/"*.md 2>/dev/null || echo '(없음)'; echo '--- git ---'; git -C "${CLAUDE_PROJECT_DIR}" rev-parse --abbrev-ref HEAD 2>/dev/null && git -C "${CLAUDE_PROJECT_DIR}" rev-parse --short HEAD 2>/dev/null && git -C "${CLAUDE_PROJECT_DIR}" status --porcelain 2>/dev/null | head -20 || echo '(git 아님)'
```

## 요청
$ARGUMENTS

## 저장 위치
- 폴더는 `${CLAUDE_PROJECT_DIR}/.claude/work/handoff/`다(프로젝트 루트 = Claude를 시작한 폴더). 없으면 만든다. OS 임시 폴더·사용자 홈에 두지 않는다.
- 다룬 파일이 프로젝트 밖에 있어도 문서는 여기에 둔다.
- 훅이나 다른 도구가 다른 경로를 안내해도 이 경로를 따른다.
- 쓰는 것은 이 폴더뿐이다. baton 작업 문서(`단계:` 포함)·소스·설정은 고치지 않는다.
- 파일명은 주제를 알아볼 수 있는 케밥케이스 `{주제}.md`다. baton 작업 문서를 이어가는 중이면 그 slug를 그대로 쓴다.
- 같은 주제를 다시 인계하면 위 목록의 같은 파일을 덮어쓴다. 살아 있는 문서는 주제당 하나다. 같은 주제인지 애매하면 묻는다.
- 덮어쓰기 전에 기존 문서를 읽는다. 아직 유효한 결정·실패한 경로·미해결 이슈는 새 문서로 옮기고, 끝났거나 뒤집힌 것만 뺀다.
- 대화에만 있는 큰 원문(탐색·검색 결과, 로그, 분석 전문)은 `handoff/refs/{주제}/{내용}.{확장자}`로 저장하고 본문에서 경로로 가리킨다. 요약만 남기고 원문을 버리지 않는다. 덮어쓸 때 `refs/{주제}/` 안에서 더는 가리키지 않는 파일은 지운다.

## 작성 원칙
- 문서는 자기완결적이어야 한다. 다음 에이전트에게 대화 기억은 없다 — 세션 안에서 만든 조어·약칭은 첫 등장에서 풀어 쓴다.
- 다른 산출물에 이미 있는 내용은 옮기지 않고 경로·URL로 가리킨다. baton 작업 문서(`.claude/work/{slug}.md`)·`docs/agent/`·PRD·계획서·ADR·이슈·커밋·diff가 그렇다.
- baton 체인 중이고 구현에 필요한 결정이 대화에만 있으면, 주의사항에 "`/baton:draft {slug} …`로 작업 문서에 넣을 것"이라고 적는다. implement는 작업 문서·docs/agent·코드만 근거로 쓴다.
- 경로·URL·명령·식별자는 요약하거나 바꿔 쓰지 않고 원문 그대로 옮긴다.
- 경로는 프로젝트 루트 기준 상대 경로에 `/` 구분자로 쓴다. 프로젝트 밖 파일만 절대 경로로 쓴다.
- API 키·비밀번호·토큰·개인 식별 정보는 값을 옮기지 않고 `<가림: 무엇인지>`로 적는다. refs 파일도 같다.
- 본문은 짧게 유지하고 무게는 포인터에 싣는다.
- 요청이 있으면 다음 세션에서 집중할 작업으로 보고 그에 맞춰 쓴다. 없으면 대화의 마지막 목표를 기준으로 쓴다.
- 문서는 대화에서 쓴 언어로 쓴다.

## 문서 구조
- **머리**: 작성일(위 `오늘:`) · 기준(git이면 브랜치·커밋 해시·미커밋 변경 유무, 아니면 생략) · 두 줄 규칙:
  - "세부가 필요하면 재조사하지 말고 아래 원문 포인터를 먼저 역참조하라."
  - "작업이 끝나면 이 문서와 `refs/{주제}/`를 지운다."
- **작업 목표**: 무엇을 하려는가.
- **확정된 결정 (재론 금지)**: 결정 + 한 줄 근거. 다음 세션이 같은 논의를 반복하지 않게 한다.
- **진행 상황**: 완료 / 진행 중 / **시도했다 실패한 경로**(같은 막다른 길을 다시 파지 않게).
  - **검증 상태**: 빌드 ○/× · 테스트 결과 · 마지막으로 확인된 동작. 실행하지 않은 것은 `미확인`으로 적는다.
- **다음 단계**: 이어받은 에이전트가 바로 시작할 수 있는 행동.
- **원문 포인터**: 코드는 `파일:줄`(이름 있는 대상은 `파일#심볼`). 계속 편집되는 문서(작업 문서 등)는 줄 번호 대신 헤딩 이름으로 가리킨다 — 편집마다 줄 번호가 어긋난다. `refs/`에 저장한 원문.
- **주의사항 / 미해결 이슈**: 막힌 지점, 사람이 결정해야 할 것.
- **다음에 부를 것**: 다음 세션에서 쓸 스킬·명령. baton 체인 중이면 다음 단계 명령(예: `/baton:implement {slug}`).

## 종료 절차
1. 문서의 포인터를 하나씩 실제로 역참조한다 — 경로는 존재, `파일:줄`은 그 줄이 문서가 말하는 내용인지, `파일#심볼`·헤딩은 그 이름이 실제로 있는지. 깨진 포인터가 하나라도 있으면 고친다.
2. 문서와 refs에 비밀값이 남지 않았는지 다시 훑는다.
3. 문서 경로와 이어받는 법 한 줄을 보고한다: 새 세션(또는 `/clear` 뒤)에서 "`.claude/work/handoff/{주제}.md` 읽고 이어서 진행해".
