## 현재 상태
```!
echo "프로젝트: ${CLAUDE_PROJECT_DIR}"; grep -H '^단계:' "${CLAUDE_PROJECT_DIR}/.claude/work/"*.md 2>/dev/null || echo '(작업 문서 없음)'
```

## 진입 조건
- 호출 전문: `$ARGUMENTS`
- 작업 폴더는 `${CLAUDE_PROJECT_DIR}/.claude/work/`다.
- 대상 문서: 인자 slug(`$slug`)가 있으면 작업 폴더의 `$slug.md`, 없으면 위 목록의 미완 문서가 정확히 1개일 때 그 문서. 아니면 멈추고 묻는다.
- 대상 문서가 `단계: 승인대기`여야 한다. 아니면 멈추고 알린다.
- 결과 수용·테스트 수집 전에 `## 인계`의 리뷰 기준 파일을 읽고 대상 루트·계획 Files·누적 변경 파일의 합집합을 같은 방식으로 다시 펼쳐 파일 목록·존재 여부·SHA-256을 대조한다. 대조는 여기서 한 번만 한다. 기준이 없거나 읽을 수 없거나 달라졌으면 바뀐 경로(또는 사유)를 보이고 다시 리뷰할지 수용할지 묻는다. 호출의 "수용"으로 대신하지 않는다. 다시 리뷰면 `/baton:inspect {slug} 재검토`를 안내하고 끝낸다 — 단계는 `승인대기`로 두고 이전 테스트 결과로 종결하지 않는다. 수용이면 `## 종결`에 "수용: 리뷰 뒤 바뀐 파일 {경로} — 사람 결정"(기준이 없거나 읽을 수 없으면 "수용: 리뷰 기준 없음 — 사람 결정")으로 적고 계속한다. 여기서 기준을 새로 만들거나 덮어쓰지 않는다.
- 사람에게 보이는 글(질문·보고)은 작업 문서와 같은 언어(한국어·영어 등)로 쓴다. 호출 인자가 영문 slug뿐이어도 그렇다.

## 절차
0. `## 인계`에 미해결 블로커가 있으면 수용 여부부터 묻는다(호출에 "수용"이 적혀 있으면 묻지 않는다). 수용이면 `## 종결`에 "수용: 항목 — 사람 결정"으로 적고 계속한다. 아니면 `/baton:draft {slug} …`를 안내하고 끝낸다.
1. 사람 테스트 결과 수집 — 호출에 결과가 적혀 있으면 그대로 쓴다. 없으면 `## 인계`의 사람 테스트 항목을 `AskUserQuestion`으로 순서대로 묻는다.
   - 한 호출에 최대 4항목. 선택지는 `y 기대대로` / `n 다름` / `안 함`. 메시지·관찰값은 Other 자유 입력으로 받는다. 질문과 보고는 작업 문서와 같은 언어로 쓴다.
   - 답을 항목 옆에 기록한다: y → PASS, n → FAIL(받은 메시지·관찰값을 함께), 안 함 → 미검증.
   - `n`과 오류 메시지는 지적이다. 지적이 있으면 여기서 고치지 않는다 — 코드 문제면 `/baton:inspect {slug}`, AC 변경이면 `/baton:draft {slug} …`를 안내하고 끝낸다. 단계는 `승인대기`로 둔다.
2. 커밋 초안 확정 — `## 인계`의 초안을 최종 트리에 맞춘다: `git status --short`와 파일 목록 대조, 경로 지정 add, 무관 변경 제외. 커밋은 사람이 한다. 호출 전문에 "커밋까지"가 있을 때만 실행한다. push는 하지 않는다.
   - 커밋이 실패하면 다시 시도하지 않는다. 실패 출력과 훅이 바꾼 파일을 보고하고 끝낸다. 단계는 `승인대기`로 둔다.
3. 작업 이력 — 작업 폴더의 `ledger.md`에 한 줄 덧붙인다. 없으면 아래 머리글로 만든다.
   `| 날짜 | 작업 | 규모 | 리뷰 회차 | 사람 개입 | 누출 단계 | 비고 |`
   - 사람 개입: 게이트 밖에서 사람이 끼어든 횟수(구현·리뷰 도중 되돌림·재질문).
   - 누출 단계: 뒤에서 잡힌 결함이 원래 걸러졌어야 할 단계(`계획`·`구현`·`리뷰`·`없음`). 사람 테스트가 전부 미검증이면 `미정`.
   - 헤더에 `묶음:` 줄이 있으면 비고에 `묶음 {이름} n번`을 적는다. 헤더 `규모:` 근거에 `분할 제안 거절`이 있으면 규모 칸에 `정규(분할 거절)`로 적는다 — 거절한 작업이 실제로 더 꼬였는지 나중에 견준다.
4. 주의 사항 제안 — 이번 작업에서 누출 단계가 `없음`이 아니었거나, 리뷰·사람 테스트에서 이 저장소 고유의 함정이 드러났으면 `docs/agent/gotchas.md`에 넣을 한 줄(`무엇을 하면 · 무엇이 깨지는가 · 근거`)을 보고에 제안한다. 직접 쓰지 않는다 — 사람이 승인하면 쓴다. `docs/agent/`가 없으면 제안하지 않는다. 조건 밖이면 `주의 사항 제안: 없음`으로 적는다. 계획·반증 단계에서 미리 잡힌 것은 해당 없음.
   - 작업 문서 `### 전제`에 `(확인 못 함의 답 {날짜})`가 붙은 줄이 있으면, 프로젝트 문서의 그 질문을 지우고 대신 넣을 한 줄도 같은 방식으로 제안한다. 근거는 `답: {답한 사람} {날짜}`로 적는다. 넣을 구역은 답의 성격으로 고른다 — 코드·도구의 동작이면 `## 함정`, 이 기계·배포·저장소의 상태면 `## 환경`, 사람이 정한 범위면 `## 경계`, 되돌리기 어렵고 · 맥락 없이 보면 이상해 보이고 · 실제 대안이 있었던 선택이면 `## 결정`.
5. `## 종결`에 테스트 결과 요약·커밋 상태를 적고, 단계를 `완료`로 바꿔 문서를 작업 폴더의 `done/`으로 옮긴다. `done/`에 같은 이름이 이미 있으면 옮기기 전에 묻는다. 이 작업의 `scratch/{slug}.*`는 지운다. `snapshots/{slug}/`는 이 작업이 커밋된 뒤에만 지운다. 커밋 전이거나 대상이 git 저장소가 아니면 남긴다(작업 전 상태의 유일한 원본).
6. 묶음 — 헤더에 `묶음:` 줄이 있을 때만 한다. 작업 폴더의 `{묶음}.bundle.md`에서 이 작업 줄을 `[x]`로 바꾸고 `갱신일:`을 고친다.
   - `[ ]` 줄 가운데 선행이 전부 `[x]`인 작업을 보고 끝에 `다음: /baton:draft {slug}`로 안내한다. 여럿이면 전부 보인다 — 고르는 것은 사람이다.
   - `[ ]`가 하나도 남지 않으면 묶음 문서도 `done/`으로 옮기고 묶음이 끝났다고 알린다.
   - 묶음 문서가 없으면 고치지 않고 그 사실만 보고한다.

## 완료 조건
- 리뷰 기준과 현재 대상 일치(다르면 사람의 수용 기록) / 사람 테스트 항목마다 결과 기록 / 커밋 해시(사람이 할 것이면 "사람 커밋 예정") / 작업 이력 한 줄 / 문서 이동 / 묶음에 속한 작업이면 묶음 문서의 그 줄 `[x]`.
